## 1. Scope and approach

The security model covers the **control plane** (Go API + Next.js console + PostgreSQL),
the **data plane** (OpenResty gateway + Coraza waf-engine sidecar), and the contract
between them (signed, hash-verified config bundles and event streams).

Threat modeling follows STRIDE across four trust boundaries (below). Security is
enforced at every layer: network, transport, authentication, authorization, data,
and operations.

---

## 2. Trust boundaries

| # | Boundary | Sides | Trust posture | Key controls |
|---|---|---|---|---|
| TB1 | Internet ↔ Gateway | Untrusted clients vs service-facing edge | Untrusted | TLS termination; strict HTTP parse (reject ambiguous CL/TE); size limits; detection-only WAF with fail-open engine |
| TB2 | Gateway ↔ Backends | Gateway vs application backends | Trusted network, sanitized requests | Trusted proxy headers set by gateway; upstream host pinned; no request bodies/cookies/credentials logged |
| TB3 | Gateway ↔ Control Plane | Data plane vs management plane | Mutually authenticated (mTLS in Phase 4; signed bundles now) | Config bundles signed (ed25519) + SHA-256 hash verified by gateway; control plane never in traffic path |
| TB4 | Admin ↔ Control Plane | Authenticated users vs management API/UI | Authenticated + authorized | HTTPS-only; management network binding; RBAC (7 roles); session-cookie auth + TOTP MFA; CSRF protection; audit on every mutation |
| TB5 | Control Plane ↔ PostgreSQL/Redis | API vs state stores | Trusted internal | DB creds via env/secrets; least-privilege roles; sensitive values not stored in plaintext where avoidable |
| TB6 | Gateway ↔ Event Collector/OTel | Sidecars on same node | Trusted sidecar | Non-blocking stdout transport; fail-open (never gated on log write) |

## 3. Threat model summary

The full STRIDE table is in `phase0_srs.md` §9.2. High-level threat classes and their
mitigations:

| Threat class | Example | Mitigation status |
|---|---|---|
| Request smuggling / parser confusion | Conflicting CL/TE | Strict single-parse-path rejection (FR-0.1-015); conformance tests |
| Unauthorized control-plane access | Credential guessing, exposed mgmt port | Management-network binding, no default passwords, session cookies, rate limits |
| Session hijacking / fixation | Stolen cookie, session reuse | HTTP-only + Secure + SameSite cookies, session rotation (`/auth/refresh`), MFA |
| CSRF on management API | Cross-site state change | SameSite cookies, Origin checks, method enforcement, audit trail |
| WAF bypass / evasion | Encoding tricks, CRS evasion | Coraza single normalization + detection; replay corpus (sqli/xss/cmdi/lfi/traversal) |
| Rate-limit / IP-list bypass | `X-Forwarded-For` spoofing | Trusted proxy headers generated by gateway only; per-IP + policy-scoped limits |
| Config tampering / partial activation | Rogue config injection | Signed, versioned, hash-verified bundles; atomic activation; last-known-good restore (ADR-003) |
| Log injection / data leak | Payloads or secrets in logs | Sensitive-field masking (rule 5); structured JSON; no bodies/cookies/credentials |
| Resource exhaustion | Oversized requests, brute force | Request size limits; rate limiting; conn limits |
| Audit tampering / repudiation | Delete or alter audit rows | Append-only immutable audit events; Auditor read-only role |
| SSRF to backends | Host/header manipulation | Upstream host pinned; backends only from config-defined nodes; trusted proxy headers set by gateway |

## 4. Authentication

- **Login:** `POST /api/v1/auth/login` (email + password) sets an HTTP-only, Secure,
  SameSite session cookie (`shield_session`).
- **Session rotation:** `POST /api/v1/auth/refresh`; logout invalidates server-side.
- **MFA:** TOTP via `/api/v1/auth/mfa/{enable,verify,disable}` — enable, verify, disable
  endpoints implemented in the control API.
- **Break-glass:** `POST /api/v1/auth/break-glass` (Phase 8 design; route exists).
- **Password change:** `POST /api/v1/auth/password/change`.
- **No default passwords:** admin credentials are generated/required at first boot
  (`ADMIN_INITIAL_*` env; `config.go` fails fast if unset).
- Dev only: role mocks are gated behind `AUTH_MOCK_ENABLED` — never enabled in production.

## 5. Authorization (RBAC)

- 7 roles: **Super Admin, Platform Admin, Security Admin, App Owner, SOC Analyst,
  Auditor, Read Only**.
- Enforced centrally by the `RBACEnforcer` middleware in `apps/control-api` (runs after
  `Auth` middleware). All 300+ API routes are covered by the enforcer's path/role map.
- **App Owner** access is scoped to owned applications (tenant isolation test required).
- Groups and role assignment: `GET/POST /api/v1/groups`, `GET /api/v1/roles`,
  `POST /api/v1/users/{id}/roles`, `DELETE /api/v1/users/{id}/roles/{roleId}`.

## 6. Data protection

| Data | Class | Handling |
|---|---|---|
| Client request bodies, cookies, credentials | **Sensitive** | Never stored or logged (rule 5) |
| Config bundles + TLS cert refs | Confidential | Write-ahead store + PostgreSQL; signed; never key material in logs |
| Audit events | Confidential | Append-only, immutable, lossless (NFR-0.1-005/014) |
| Access/security events | Internal | Masked, no payloads; retention default 30 days (see OQ-2 resolution) |
| Secrets (API keys, integrations) | Confidential | Stored as references/hashes; envelope encryption at rest targeted for later phases |

**Masking (rule 5):** the event ingestor masks sensitive fields before persistence; the
WAF engine masks payloads in events (see `mask` endpoints). No secrets, cookies, or
credentials ever appear in logs.

## 7. Logging policy

- **Access events:** structured JSON, best-effort, non-blocking, fail-open — a logging
  failure never blocks or crashes the traffic path (master plan §22, FR-0.1-033).
- **Audit events:** durable, append-only, lossless; every config mutation is audited
  (actor, action, resource, before/after ref, timestamp, request ID).
- **Security events:** engine → event-ingestor → PostgreSQL `security_events`;
  Wazuh/syslog forwarder adapter available.
- **Retention:** access logs 30 days by default (configurable via
  `GET/PATCH /api/v1/settings/retention`).
- **Masking:** bodies, cookies, and credentials are excluded at the source.

## 8. Transport & network

- HTTPS-only management API (bind to management network by default, `127.0.0.1` in compose).
- TLS termination uses maintained system libraries (OpenResty/OpenSSL) — no custom TLS (NFR-0.1-010).
- Config bundles signed (ed25519) and hash-verified by the gateway; mTLS between gateway
  and control plane planned for Phase 4 (ADR-004).

## 9. Operational security

- CI: gosec SAST, `govulncheck` dependency audit, trufflehog secret scan, i18n check,
  schema golden checks, replay corpus, failover drills.
- No secrets in code or config defaults; `.env` never committed.
- SBOM and signed artifacts are a release gate (SRS §11).
- Production/F5-class capability claims require evidence from the QA program
  (master plan rule 10 / AGENTS.md).
