1. System Architecture Overview

Welcome to Ariba Shield WAF, an enterprise-grade Web Application Firewall. Built upon a powerful OpenResty gateway and powered by a Coraza detection engine, it protects your infrastructure against zero-day exploits and OWASP Top 10 vulnerabilities (SQLi, XSS, Command Injection, Traversal, LFI).

Key Design Principles:

  • Safe Config Lifecycle: Validations are strict. Invalid configurations cannot break the active listener. Automatic rollback to the last-known-good configuration ensures zero downtime.
  • Event Masking: Sensitive payloads and tokens are masked to ensure PCI/PII compliance in logs.
  • Out-of-Path Control Plane: The management API and Web Console run entirely out-of-band and will never slow down live traffic routing.

4. Role-Based Access Control (RBAC)

Ariba Shield incorporates a granular 7-tier Role-Based Access Control (RBAC) system. Depending on your assigned role, certain features will be restricted or read-only:

Role Permissions Overview
Super AdminFull access to all system settings, user management, and policies.
Platform AdminManages gateway lifecycles and global configurations.
Security AdminManages virtual servers, blocklists, rate limits, and WAF rules.
App OwnerManages backend pools and routing only for applications they own.
SOC AnalystRead-only access to traffic logs, incidents, and security events.
AuditorRead-only access strictly for configuration state and audit logs.
Read OnlyBasic read access to visual dashboards.

5. Analytics Dashboard

The main Overview Dashboard contains 8 distinct widgets that provide a real-time, birds-eye view of your network's security posture.

  • Metric Cards: Total Applications, Active Gateways, Enforced Policies, Security Events, and Active Incidents — all fed by the live /dashboard/overview API.
  • Traffic Summary: Total requests, average latency, P99 latency, and a status-code breakdown for the last 7 days.
  • Security Summary: Total events, blocked count, unique IPs, and a severity distribution (critical/high/medium/low).
  • Top Client IPs: The source IPs generating the most events, with blocked counts.
  • Top Triggered Rules: Which WAF rules (e.g., SQL Injection, XSS) are intercepting the most traffic.
  • Protected Applications: A list of onboarded applications with live status badges.

All widgets accept an optional days window (default 7, max 90).

6. How to Protect a Website (Onboarding)

The primary function of the WAF is to intercept traffic intended for your web applications, sanitize it, and forward it to your backend servers. Follow these steps to onboard a new website:

  1. Create an Application: Navigate to the Applications menu. Create a new logical grouping for your services (e.g., "E-Commerce Frontend").
  2. Define Backend Pools & Nodes: Within the application, configure a Backend Pool. Add your actual backend servers (Nodes) using their internal IP addresses and ports (e.g., 10.0.0.15:8080). Ensure you configure Health Checks to automatically bypass down nodes.
  3. Configure Virtual Servers: Go to Virtual Servers. Define the public-facing domain (e.g., www.example.com) that the WAF will listen on, and attach TLS certificates if HTTPS is required.
  4. Route Traffic: Map the Virtual Server path to the Backend Pool you created earlier.
  5. Apply Security Policies: Attach WAF rule bundles, configure rate limits, and assign IP blocklists to protect this specific application route.
  6. Deploy Configuration: Click the Deploy button. The WAF will perform a strict validation check and atomically reload the OpenResty gateway with zero downtime.

7. Security Management Features

Policies Virtual Servers & Rate Limiting

Define how the WAF treats incoming traffic. You can enable or disable specific OWASP core rule sets. In Phase 3 routing, you have direct control over Rate Limiting, IP Allow/Block lists, and custom backend pool routing.

Threats Incident Management

Ariba Shield features a full Incident Response module. SOC Analysts can view incidents, assign them to team members, escalate severities, and view a timeline of related WAF trigger events.

Monitoring Security Events & Audit Logs

Every configuration mutation produces an immutable audit event (recording the actor, action, timestamp, and request ID). Additionally, every blocked payload is logged in the Security Events ledger (with sensitive data masked) for deep inspection.

Analytics Reports

Generate, view, and download comprehensive security reports for compliance auditing in PDF or CSV formats.

9. Integrations & Notifications

SIEM & Log Forwarding Integrations

Forward WAF events and access logs to your security stack. Go to Integrations to manage log-forwarding targets. Supported types:

  • SIEM: Splunk HEC, Wazuh, Syslog
  • Messaging: Microsoft Teams, Slack
  • Custom: Generic Webhook

Each integration supports a Test button to validate connectivity, plus Enable/Disable toggles.

Notification Channels

Configure alert delivery for incidents and critical events under Notification Channels. Supported kinds: Wazuh, Syslog, CEF, LEEF, Webhook, Email, Microsoft Teams, Slack, and SOAR. Mark one channel as default to receive all system alerts.

10. Certificates & Backups

TLS Certificate Management

Upload, import, renew, and monitor TLS certificates under Certificates. Expiring or expired certificates are color-coded (green = valid, yellow = expiring soon, red = expired).

Backups & Disaster Recovery

Trigger encrypted database backups and restore them from the Backups page. Restore operations require confirmation because they overwrite the current configuration.

11. Threat Intelligence

Manage threat intelligence feeds that dynamically block malicious IPs, domains, URLs, and ASNs. Under Threat Intelligence you can:

  • Create feeds by source with an indicator type (IP/Domain/URL/ASN) and a confidence level.
  • Test feed connectivity and Sync the latest indicators on demand.
  • Monitor feed status and indicator counts at a glance.

12. Learning & Policy Suggestions

The Learning module builds policy suggestions from trusted sources only. It can never directly weaken an active policy — every suggestion must be reviewed and explicitly accepted.

  • Sessions: Create trusted-source learning sessions with a confidence threshold, then start/stop them.
  • Suggestions: Review engine-generated rule suggestions (rule ID, severity, confidence, rationale). Use Accept to gate a policy update through the approval workflow, or Reject to discard.

13. License Management

If commercialized, the platform uses edition-based licensing. Under License you can:

  • View the active edition (Community / Pro / Enterprise), seat count, and expiry date.
  • Monitor usage against limits (gateways, applications) with percentage bars.
  • Activate a license key, or deactivate to revert to the Community edition.
  • Review the granted feature entitlements for your edition.

14. Troubleshooting & Recovery

API Offline Error

If the dashboard displays an "API Offline" badge, the frontend is unable to reach the backend API. Ensure that the NEXT_PUBLIC_API_BASE is correctly mapping to your hostname via Docker compose, and that no external firewalls are blocking port 8443.

Gateway Reload Failure

If an invalid configuration is somehow forced into the NGINX/OpenResty node, the Gateway will automatically detect the failure and revert to the last-known-good configuration natively, logging the failure in the Audit trail.
